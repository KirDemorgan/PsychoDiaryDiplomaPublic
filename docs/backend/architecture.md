# Архитектура бэкенда

Модульный монолит: Java 25, Spring Boot 4.1.1, PostgreSQL, Liquibase. Документ фиксирует принятые решения, причины и ограничения. Контракт API — в [api.md](api.md).

## Состояние

Написаны: авторизация и изоляция, оценки, записи с редакциями, препараты и приёмы, теги, календарь и аналитика, снимки отчётов и PDF, экспорт и удаление аккаунта, очередь AI-задач, голосовой ввод, HTTP-адаптеры Ollama и ASR.

Проверки: `mvn clean verify` — 179 модульных тестов и порог покрытия JaCoCo 80 %; интеграционные сценарии с PostgreSQL выполняются в GitHub Actions. Сервер развёрнут с HTTPS. Модели (Ollama `gemma4:e4b` и сервис распознавания речи GigaAM v3 e2e) работают на отдельном компьютере с GPU и доступны серверу через Tailscale (`LLM_TIMEOUT=PT150S` из-за холодной загрузки модели).

Не сделано: проверка на физическом iPhone; длинные записи диктовки (временный предел 25 с, см. раздел 13).

## Структура кода

`alex.drankov.diary`: `auth`, `users`, `ratings`, `entries`, `medications`, `tags`, `analytics`, `reports`, `exports`, `ai`, `speech`, `security`, `config`, `common` (api, crypto, persistence, mapping, idempotency). Внутри модуля — `controller / dto / service / entity / repository / mapper`. Публичные DTO — отдельные файлы; JPA-сущности наружу не публикуются; MapStruct с запретом незамеченных полей. Без микросервисов, Kafka, лишних Maven-модулей и интерфейсов без второй реализации.

Стиль: `.editorconfig` (4 пробела, отдельные аннотации, параметры по одному на строку), явные импорты, комментарии только для неочевидных ограничений. Тесты: `@DisplayName` на русском, параметризованные — с `name = ...`.

## Решения

### 1. Stateless HTTP и отзыв доступа через БД
Bearer JWT на каждый запрос (подпись, issuer, audience, срок, активность сессии в БД). Каждый вход — новая сессия того же пользователя (несколько устройств); logout и повторное использование refresh отзывают только свою сессию. Причина обращения к БД: мгновенный отзыв уже выданного JWT при logout и удалении аккаунта. Цена: каждый защищённый запрос зависит от БД. BCrypt cost 12 (пароль ≤ 72 байт UTF-8); access 15 минут; refresh — случайный, в БД SHA-256, ротация, срок сессии до 30 дней; повтор потреблённого refresh отзывает сессию. Лимит попыток входа — в памяти одного процесса (не распределённый). CSRF выключен (Bearer без cookie), CORS — явный список origins (bean `corsConfigurationSource`).

### 2. Изоляция владельцев и транзакции
ID пользователя берётся из JWT. Дочерние ресурсы ищутся по паре «id + владелец», чужой — 404. Мутации сначала блокируют строку пользователя: операции одного владельца сериализуются (простота ценой параллелизма; пересмотреть при нагрузке).

### 3. Версии и идемпотентность
`@Version` и ETag `"vN"`: для существующего ресурса нужен `If-Match` (нет — 428, устарел — 412). `version` — контроль конкурентных правок, `revision` — неизменяемый снимок текста записи. `common/idempotency`: `Idempotency-Key` (UUID клиента) + хеш тела + маршрут + владелец в `mutation_receipt`; тот же запрос возвращает прежний ответ, другое тело — 409. При удалении payload стирается и остаётся tombstone (повтор — 410). Срока жизни ключей пока нет, кроме жизни аккаунта — решение для согласования.

### 4. Типизированные PATCH
Отдельные DTO (`UpdateProfileRequest`, `UpdateSettingsRequest`, `UpdateEntryRequest`) с явным учётом присутствия поля; явный `null` очищает только nullable-поля (имя, интервал повтора напоминания). Универсальный разбор JsonNode удалён. Jackson: неизвестные поля и неявные приведения типов отклоняются.

### 5. Данные, время, миграции
Liquibase — единственный источник схемы; `ddl-auto=validate`; Open Session in View выключен. Миграции 001–008, 20 прикладных таблиц (см. [ERD_actual](../diagrams/ERD_actual.md)). Jackson 3: `spring.jackson.datatype.datetime.adjust-dates-to-context-time-zone=false`, иначе +05:00 превращалось в UTC до проверки IANA-зоны. Событие хранится как абсолютное время + IANA-зона; offset проверяется на соответствие зоне. Период — `[начало from; начало дня после to)`, максимум 366 дней. Оценка уникальна по (владелец, localDate, слот). Запись 1–5000 code points; правка текста/времени/зоны создаёт редакцию, смена `reportVisible` — нет.

### 6. Приватность и ошибки
`ProblemDetail` + стабильный `code` + `traceId`; `Cache-Control: no-store`; пароли, токены и тексты не попадают в `toString` и логи. Swagger только в профиле `local`. Развёрнутый сервер доступен по HTTPS (Caddy, автоматический сертификат); локальный HTTP допустим только для разработки.

### 7. Препараты
Таблицы `medication`, `schedule_version`, `schedule_slot`, `intake_event`. Плановые дозы не материализуются — вычисляются из слотов, версии и зоны при чтении (до 366 дней). `occurrenceId` — opaque, кодирует слот и время. Версии упорядочены, вставка перед запланированной запрещена; предыдущая закрывается новой (явный flush из-за уникальности открытой версии). Зона хранится в версии, смена профиля её не меняет. DST: пропущенное время переносится к моменту перехода, повторяющееся даёт одну дозу с ранним смещением. Архив ограничивает будущие приёмы, DELETE каскадно стирает всё. Уведомления — на клиенте.

### 8. Теги и история ревью
`tag_review` (неизменяемые снимки полной замены), `entry_tag`, `diary_entry.current_review_id`; составные и deferred FK привязывают ревью к конкретной редакции. Правка текста сбрасывает текущее ревью, история остаётся. Проверка запрещает разрезание emoji, выдуманные цитаты и повтор кода на одном фрагменте. Для аналитики нужны подтверждённая дата, PRESENT, SELF и не FUTURE. Ревью можно завершить без тегов.

### 9. Аналитика
`AnalyticsCalculator` — чистый расчёт без БД; сервис читает данные в транзакции PostgreSQL REPEATABLE READ (согласованный календарь, показатели и `dataRevision`). Средние и доли — BigDecimal, 4 знака HALF_UP, доли 0–1. Выполнение = принятые / весь план; покрытие = отмеченные / весь план; внеплановые не считаются. Группы сравнения — по правилам из Business_rules (≥ 5 дней, исключение неполного/противоречивого контекста).

### 10. Отчёты и PDF
Миграция 005, таблица `report`. Создание под блокировкой владельца: выборка, статистика, цитаты, ссылки на источники и данные предпросмотра — в одном снимке. Факты имеют типы, значения и SHA-256 `factId`; `sourceRefs` указывают ID, версии, редакции. Хеш входа включает выборку, факты и предпросмотр, но не текст обзора. ALL_VISIBLE исключает скрытые записи; EXPLICIT проверяет владельца, период и видимость; NONE и снятые разделы убирают источники до расчёта фактов. До подключения модели — `TemplateOverview` (происхождение TEMPLATE, `MODEL_NOT_CONFIGURED`). PDF: Thymeleaf → OpenHTMLtoPDF/PDFBox 3, графики рисует Java2D с разрывами на пропусках, шрифт DejaVu (кириллица), только собственные PNG data URI, пользовательский HTML экранируется, файл в памяти и `no-store`. Актуальность проверяется по `dataRevision` (консервативно: любое изменение данных делает снимок устаревшим → `409 REPORT_STALE`). Схемы: [PlantUML](../diagrams/plantuml/README.md), [Excalidraw](../diagrams/PDF_generation.excalidraw).

### 11. Экспорт и удаление
ZIP формата `diary-export-v1` (JSON всех данных владельца + описание формата), формируется синхронно под блокировкой, хранится в `bytea` до 24 часов, очистка каждые 15 минут. Пароль, сессии, токены и receipts не экспортируются; скрытые из PDF записи в полный экспорт входят. Лимиты: 10000 строк на таблицу, 64 МиБ JSON (413). Миграция 006: SQL-триггер при смене `dataRevision` в той же транзакции стирает чувствительные снимки отчётов и архивы (необратимо) и превращает связанные receipts в tombstone. `DELETE /me` требует текущий пароль и `confirm=true`, каскадом стирает всё и мгновенно лишает доступа сессии. Будущие worker обязаны брать ту же блокировку и не публиковать результат после удаления.

### 12. Очередь AI-задач
PostgreSQL-очередь (`ai_task`, ENTRY/REPORT) без новых библиотек; worker опрашивает с fixed delay. Захват и публикация — в `AiQueue` (`@Transactional`), вызов модели — между транзакциями. RUNNING получает lease-token и срок timeout + 30 с; максимум две попытки; публикация перепроверяет владельца, токен, срок, статус, согласие, хеш и редакцию. SQL-триггеры инвалидируют активную задачу при правке/завершении ревью, смене данных отчёта, отключении AI. `ModelGateway`: таймаут `LLM_TIMEOUT` (по умолчанию 30 с, на сервере 150 с), одна параллельная операция, отмена Future. Сырые ответы и тексты в логи не пишутся.

Извлечение: строгий JSON до 65536 символов и 100 кандидатов; цитата обязана существовать в тексте (для повтора — occurrence); позиции считает сервер. Если цитата встречается в тексте один раз, `occurrence` игнорируется (модели путали его с номером кандидата); для повторяющейся цитаты он проверяется. Промпт `entry-extraction-v2` поясняет, что `temporal` считается относительно дня записи, а не по времени глагола. Кандидаты хранятся отдельно (`analysis_candidate`); решения пользователя — ACCEPT/EDIT/REJECT/PENDING для каждого, неизменяемая история; полное ревью запрещает PENDING. Обзор (промпт `report-overview-v6`, схема `report-narrative-v1`): модель получает факты, кроме цитат (QUOTE), с короткими id (F1, F2…) без хешей и ссылок на источники; цитаты PDF выводит отдельным блоком, в запрос обзора они не попадают (решение владельца 24.10.2026: цитаты были главной причиной отказов проверки, на dev принятие выросло с 0,2–0,5 до 0,6–1,0) (в первом dev-прогоне модели путали 66-символьный `factId` с UUID из `sourceRefs`) и возвращает 1–8 пунктов `{text, factIds}` с этими id (до 600 знаков и 8 фактов в пункте, до 3000 знаков всего; отказ проверки не повторяется, сразу публикуется шаблон, повтор только для сбоев транспорта), `sourceRefs` вычисляет сервер из цитируемых фактов. `NarrativeGuard` проверяет: пункт не может ссылаться только на цитаты; нет диагностических, причинных, лечебных и рекомендательных слов (разрешены оговорки вроде «Это связь, а не доказанная причина.»); цитаты в «» дословны; даты (ISO, дд.мм.гггг и словами «5 октября [2026 года]») и числа взяты из `allowedText` цитируемых фактов (допускаются день, месяц и год разрешённых дат; дата словами без года сверяется по дню и месяцу, с годом — полностью); слова-числа («семь») запрещены. Любой неверный пункт отклоняет весь ответ, повтора нет, сразу TEMPLATE с причиной (повторяются только сбои транспорта). Ограничение: проверка не видит смысла (например, неверное «выше/ниже» или «улучшение», которого нет в фактах), это измеряет исследование. Прежняя закрытая грамматика v1 (модель только выбирала готовые формулировки) удалена из сервера и остаётся как контрольный вариант в `research/`. Отчёт без AI сразу READY; с AI: QUEUED → RUNNING → READY (AI или TEMPLATE); PDF до READY запрещён.

### 13. Голосовой ввод (X04)
Модуль `speech`, миграция 008 (`transcription`, согласие в `user_settings`). Отдельное согласие `diary-speech-v1` (требует общего AI). Формат WAV PCM16 mono 16 kHz, 0,1–120 с, до 4 MiB, проверяется по структуре контейнера, а не по MIME. Один активный запрос на пользователя, 30 загрузок в час. Очередь с lease и до двух попыток; аудио в `bytea` живёт ≤ 15 минут и стирается при завершении/отмене/отзыве согласия; текст — 24 часа; метаданные удаляются через 7 дней после истечения. Расшифровка не становится записью автоматически и не входит в PDF; ZIP включает текст, но не WAV. ASR-сервис должен реализовать собственный контракт: `POST` WAV с заголовками `X-Speech-Model`, `X-Speech-Language: ru` → `{"text","modelId"}` (ответ ≤ 64 KiB, строгая проверка). Конфигурация: `SPEECH_ENDPOINT`, `SPEECH_MODEL_ID` (обе или ни одной), `SPEECH_TOKEN`; таймаут `PT60S`. M4A/MP3/streaming не поддерживаются — клиент должен кодировать WAV. Временно (с 24.10.2026, до исследования длинных записей) клиент ограничивает диктовку 25 с, а ASR-сервис GigaAM отвечает 413 на записи длиннее 26 с; контракт бэкенда (до 120 с) не менялся.

### 14. HTTP-адаптер LLM
`OllamaModelAdapter`: `POST /api/chat`, system и user как разные messages, JSON Schema в `format` (`ai/schemas/entry-candidates-v1.json`, `report-narrative-v1.json`), `stream=false`, `think=false`, `temperature=0`, без инструментов. Проверяются статус 200, точный `modelId`, `done=true`, `done_reason=stop`; запрос ≤ 2 MiB, ответ ≤ 256 KiB; редиректы запрещены. Конфигурация: `LLM_ENDPOINT` (полный `/api/chat`), `LLM_MODEL_ID` (точный tag), `LLM_TOKEN`, `LLM_TIMEOUT` (PT30S), `LLM_NUM_CONTEXT` (16384), `LLM_NUM_PREDICT` (8192). Пустая пара отключает интеграцию. JSON Schema помогает формату, смысл проверяет сервер. Tag фиксирует сборку: при замене весов нужно менять идентификатор. Вместимость контекста и память под реальные пакеты фактов не измерены.

## Проверка и CI

`mvn clean verify` — unit-тесты + порог JaCoCo 80% (генерация MapStruct исключена). `mvn clean verify -Pintegration-tests` — Failsafe + Testcontainers (PostgreSQL), проверяет миграции, HTTP, владельцев, повторы, версии, триггеры. Workflow `.github/workflows/backend-ci.yaml` (PR/push в master, ручной запуск) также проверяет `docker compose config`. История инцидентов CI: первый запуск упал из-за пути настройки Jackson (исправлено, добавлен `JacksonConfigurationTest`); позднее падение `calendarAndAnalytics` исправлено по логу. Покрытие — инженерная метрика бэкенда, не показатель качества AI.

## Чего нельзя утверждать в ВКР без новых доказательств
«Работает на PostgreSQL», «CI зелёный» для новых модулей, «AI обеспечивает качество», «свободная суммаризация поддержана», «проверено на устройстве» (без журнала проверок). Перед защитой сверить документ с кодом, миграциями и журналом запусков.
